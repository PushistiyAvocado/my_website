# Персональный сайт специалиста по недвижимости — Хазиева Ксения Владимировна

Репозиторий содержит **Этап 1 — проектирование** (концепция, карта страниц, архитектура)
и **визуальный прототип** ключевых экранов, который можно открыть в браузере прямо сейчас.

## Ограничения текущей среды (важно)

1. **Node.js и npm в системе не установлены** (`node`, `npm`, `C:\Program Files\nodejs` — отсутствуют).
   Поэтому `next dev` / `npm install` здесь запустить невозможно, и прототип сознательно сделан
   без сборки: HTML + CSS + JS без единой зависимости — работает по `file://` и на любом статическом хостинге.
   Из рантаймов есть только **Python 3.14** — он используется как статический сервер (`serve.ps1`,
   `python -m http.server`).
2. **Фотографий Ксении нет.** В прототипе стоит честная заглушка с подписью
   «Фото Ксении будет добавлено». Вымышленный портрет не создавался и за реальное фото не выдаётся.
3. **Все объекты недвижимости — демонстрационные.** Они помечены бейджем «демо», цены и адреса
   не являются реальными предложениями. Контакты (телефон, Telegram) нигде не выдуманы:
   вместо них — явные поля-заглушки «заполняется в админ-панели».
4. Отзывы не сгенерированы. В блоке отзывов показано **состояние дизайна до публикации**
   («отзыв появится после модерации») — так видно карточку, но нет фальшивых историй клиентов.
5. Форма в прототипе проходит валидацию и показывает подтверждение, но **не отправляет данные**
   (бэкенда ещё нет) — об этом пользователю сообщается прямо в интерфейсе.

## Как запустить сайт для проверки

Прототип не требует сборки: это HTML + CSS + JS, которые браузер открывает напрямую. Есть четыре способа,
все проверены в этой среде.

**1. Двойной щелчок по `start.cmd` в корне папки проекта** — самый простой вариант.
Откроется чёрное окно с адресами и сразу браузер с сайтом:

- главная — <http://127.0.0.1:5173/index.html>
- каталог — <http://127.0.0.1:5173/catalog.html>

Окно закрывать нельзя, пока смотрите сайт (это и есть сервер). Остановить: `Ctrl+C` в этом окне
или просто закрыть его.

**2. То же самое через `serve.ps1`** — правый клик по файлу → «Выполнить с помощью PowerShell».
Ключи: `-Port 8080` (другой порт), `-NoBrowser` (не открывать браузер). Из терминала:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\serve.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\serve.ps1 -Port 8080 -NoBrowser
```

**Перезапуск.** Обычно он не нужен: страницы статические, изменения в `prototype\` видны по `F5`
(для `app.js`/`site.css` — `Ctrl+F5`, чтобы сбросить кеш). Перезапуск нужен, если окно сервера
закрылось аварийно и порт остался занят, или если вы правили `serve.ps1`.
Двойной щелчок по `restart.cmd` снимает процесс на порту 5173 и запускает сервер заново.
То же самое одной строкой в PowerShell:

```powershell
Get-NetTCPConnection -LocalPort 5173 -State Listen -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
powershell -NoProfile -ExecutionPolicy Bypass -File .\serve.ps1
```

**3. Без сервера вообще** — двойной щелчок по `prototype\index.html` или `prototype\catalog.html`.
Windows откроет браузер, адрес будет `file:///…`. Всё интерактивное работает и так,
потому что внешних запросов нет; отличается только адресная строка.

**4. Вручную через Python** (Python 3.14 в системе есть):

```powershell
cd .\prototype
python -m http.server 5173
```

Затем открыть <http://127.0.0.1:5173/index.html>.

Проверять нужно в двух режимах: широкий экран (≥1280px) и мобильный (DevTools → 390×844).
Изменения в `prototype\` подхватываются по `F5`, пересборка не нужна.

## Публикация на GitHub Pages

Сайт собирается **только из репозитория** `PushistiyAvocado/my_website`:
`.github/workflows/deploy.yml` при каждом push в `main` публикует папку `./prototype`.
Рабочая папка проекта и локальная копия репозитория — **два разных каталога**:

| Что | Где |
| --- | --- |
| рабочая папка, в которой правим файлы | `E:\Building web site\Недвижемость` |
| локальная копия репозитория (её и видит Source Control) | `E:\Building web site\Real_estate\my_website` |

Поэтому правка, сделанная в рабочей папке, в репозиторий сама не попадает: в VS Code
«нет изменений», хотя файлы изменены, а на сайте остаётся старая версия. Порядок публикации:

1. Двойной щелчок по **`deploy.cmd`** в рабочей папке
   (из терминала — `.\deploy.cmd "сообщение коммита"`). Скрипт копирует файлы в копию
   репозитория, делает коммит и `git push origin main`.
2. Подождать 1–2 минуты — GitHub Actions соберёт и выложит сайт,
   статус виден на <https://github.com/PushistiyAvocado/my_website/actions>.
3. Открыть <https://pushistiyavocado.github.io/my_website/> и нажать **Ctrl+F5**:
   без этого браузер отдаст старый `site.css`/`app.js` из кэша.

Ключи `deploy.ps1`: `-NoPush` — только синхронизировать файлы, без коммита; `-Mirror` — заодно
удалить в репозитории файлы, которых больше нет в рабочей папке; `-Destination` — другой путь
к копии репозитория. Черновики `_*.txt`, `_dom.html`, `_tmpc*` в репозиторий не копируются.

Альтернатива: работать прямо в `E:\Building web site\Real_estate\my_website` — тогда Source Control
видит изменения сразу, а `deploy.cmd` не нужен.

## Автоматические проверки прототипа

| Что | Как запустить | Что проверяет |
| --- | --- | --- |
| `_check.ps1` | `powershell -NoProfile -ExecutionPolicy Bypass -File .\_check.ps1`, результат — в `_check.txt` | вложенность тегов, дубли `id`, обязательные `id`, якоря без цели, `dialog[open]` в разметке, баланс скобок в JS, опечатки вида `-clamp(` в CSS |
| `_shots\test-desktop.html` | открыть в Chrome (`--allow-file-access-from-files`), либо headless с `--dump-dom` | 22 сценария на ширине 1200px: поиск, сброс, избранное, диалог, шаги маршрута, сортировка, пагинация, чипы фильтров, статичная панель фильтров |
| `_shots\test-mobile.html` | то же, что выше | 15 сценариев на ширине 390px: бургер и меню (клик, `Escape`, крестик), скрытая навигация, нижний лист фильтров, фильтр этажа, применение фильтров |
| `_shots\shot.html#filters`, `_shots\shot.html#dialog` | скриншот в headless Chrome 390×844 | визуальная проверка открытого листа фильтров и модального окна на телефоне |

Стенды-обёртки (`test-*.html`, `shot.html`, `frame*.html`) открывают прототип в `<iframe>` нужной ширины:
это обход того, что headless Chrome не создаёт окно уже ~500px. Прототип при этом не меняется.

Скрипты `*.ps1` лежат в UTF-8 **с BOM**: Windows PowerShell 5.1 иначе читает кириллицу как ANSI
и падает с ошибкой парсинга строк. Если будете править `serve.ps1`, `_check.ps1` или `deploy.ps1`
в стороннем редакторе — сохраняйте с BOM.

## Что демонстрирует прототип

- Первый экран с асимметричной композицией: фото объекта + портрет Ксении «внахлёст».
- Панель поиска, которая **реально фильтрует** демо-объекты (тип, город, район, комнаты, цена, площадь).
- Каталог: фильтры в сайдбаре (на мобильном — выдвижная панель), сортировка, счётчик, сброс, пустое состояние.
- Интерактивная временная шкала сопровождения сделки (4 этапа, переключение описаний).
- Карточки отзывов (состояние «до модерации»), карточки блога, блок «Из Telegram».
- Модальное окно «Связаться» с валидацией формы и честным сообщением о демо-режиме.
- Мобильное меню, «липкий» хедер, мягкие анимации появления с учётом `prefers-reduced-motion`.

2. Установить Node.js LTS 20/22, развернуть каркас Next.js по `docs/03-architecture.md`.
3. Перенести прототип в компоненты дизайн-системы, добавить остальные страницы Этапа 2.
4. Подключить БД, заявки, модерацию, админ-панель (Этап 3). Почта/Telegram/карта — Этап 4.
