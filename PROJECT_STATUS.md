### 4.1. «Маршрут сделки»: стрелки по бокам карточки

Стрелки листания этапов вынесены из шапки карточки **по бокам** (`6ec3e87`), затем увеличены
иконки этапа (`e012a64`: плашка 52→100px, картинка 28→50px).

- Разметка: `.route-shell` (grid `"prev detail next"`) → `.route-detail` + две `button.route__arrow`.
- `@media (max-width: 1024px)`: карточка на всю ширину, стрелки под ней, прижаты к краям
  (`grid-template-areas: "detail detail" "prev next"`, `justify-content: space-between`).
- `keydown` (`←` `→` `Home` `End`) навешен на `.route-shell` (fallback — карточка), поэтому
  клавиши работают и при фокусе на стрелке; `aria-pressed` всегда ровно один.
- Замеры: 1684/1424/1264px — стрелки по бокам, по центру по вертикали; 1008/744/500/420px —
  под карточкой; `overflowX = 0` везде.

### 4.2. Живая лента Telegram-канала без бэкенда

Прямой запрос из браузера невозможен: у `https://t.me/s/<канал>` нет `Access-Control-Allow-Origin`,
а Bot API требует токен, который нельзя держать в клиентском JS. Выбран вариант **снимок на сборке**:
лента собирается скриптом локально или в Actions и публикуется обычным JS-файлом — CORS не нужен,
токенов нет, сайт остаётся статическим.

| Файл | Роль |
| --- | --- |
| `scripts/fetch-telegram.ps1` | скачивает `t.me/s/<канал>`, разбирает посты (id, ссылка, дата, просмотры, первое фото, текст), чистит разметку по белому списку, пишет `telegram-data.js`. Ключи: `-Channel`, `-OutFile`, `-MaxPosts` (по умолчанию **50**), `-MaxChars` (700); канал также берётся из `TELEGRAM_CHANNEL` или `scripts/telegram-channel.txt` |
| `scripts/telegram-channel.txt` | единственная настройка: активная строка `@hazieva_realty`, остальное — комментарии-подсказки |
| `.github/workflows/telegram.yml` | только `workflow_dispatch` с полем `channel`; собирает файл и коммитит в `main`, дальше срабатывает `deploy.yml`. Расписания нет намеренно |
| `prototype/assets/js/telegram-data.js` | `window.HZ_TELEGRAM` — снимок ленты. Без канала файл не перезаписывается, а при отсутствии создаётся пустая заглушка (чтобы не было 404) |
| `prototype/assets/js/app.js` | `TG_MONTHS`, `tgTime()`, `tgCard()`, `tgProfile()`, `initTelegram()`, `initTgCarousel()` |
| `prototype/assets/css/site.css` | `.tg-post*`, `.tg-feed`, `.tg-wrap--start`, `.tg-carousel*`, `.tg-feed--grid`, `.tg-col`, `.tg-more`, `.tg-profile*` + `[data-tg-fallback][hidden], [data-tg-link][hidden] { display: none !important; }` |

Безопасность: текст поста вставляется через `innerHTML`, поэтому скрипт оставляет только
`b`, `strong`, `i`, `em`, `u`, `s`, `del`, `code`, `pre`, `blockquote`, `br` и ссылки `http(s)`/`mailto`;
`script`, `iframe`, `style`, `on*`-атрибуты вырезаются вместе с тегом, незакрытые теги закрываются.
Ссылки получают `target="_blank" rel="noopener nofollow"`, остальные поля выводятся через `esc()`.

Проверено на реальных каналах (`@hazieva_realty`, `@durov`, `@telegram`): эмодзи, `<br>`, ссылки,
фото `cdn*.telesco.pe`, просмотры («579 тыс.», «1,09 млн»), подписчики, название; `-Channel`
принимает `@name`, `name`, `https://t.me/name`, `t.me/s/name`, `t.me/name/123`; пустой канал →
код 0 и файл не меняется, закрытый/несуществующий → код 1; `ConvertTo-Json` для одного поста отдаёт
объект — `initTelegram()` нормализует через `[].concat(cfg.posts)`.

### 7.1. Адаптивность

1. **`telegram.html` и карусель на реальных телефонах (320–390px).** Проверено 390 и 820px;
   ниже 420px headless Chrome окно не создаёт, поэтому нужен прогон через iframe-стенд
   `_shots/frame.html` на 320/360/375/390px. Смотреть: длинное название канала в
   `.tg-profile` (не должно выдавливать кнопку «Открыть канал»), счётчик `[data-tg-count]`
   в одну строку, отступы карточек, а в карусели — не перекрывают ли стрелки 44×44 текст
   на карточке 280–335px (при необходимости уменьшить отступ с 8px до 4–6px).
   На 320px карточка поста должна остаться ≥ 280px.
2. **Длинные посты и альбомы в сетке.** Альбом из 3–4 фото при двух колонках может дать
   «лестницу» разной высоты — проверить `.tg-post__media` (сейчас `max-height: 340px` в сетке)
   и при необходимости заменить на `aspect-ratio` + `object-fit: cover`, чтобы карточки
   в ряду были одной высоты. Отдельно проверить пост **без фото** (карточка не должна
   «схлопываться») и пост с текстом ровно на 700 знаках (обрезка + «Читать в Telegram»).
3. **Плашка иконки 100×100 в «Маршруте сделки».** Шапка карточки — `flex` + `flex-wrap:
   wrap` + `justify-content: space-between`; на 720/480/420px нужно убедиться, что заголовок
   не превращается в «столбик слов». Если жмёт — `clamp(64px, 9vw, 100px)` для плашки и
   `clamp(32px, 5vw, 50px)` для картинки, либо вернуть иконку в `.route-detail__head-text`
   как строчный элемент.
4. **Граница 1024/1025px и 860px.** Перестроение «стрелки по бокам → под карточкой»
   происходит ровно на 1024px — проверить 1024 и 1025 отдельно (на 1025 карточка ~840px,
   переносов слов в заголовке быть не должно). Отдельно 860px — переход `.tg-feed--grid`
   2 → 1 колонка: не должно остаться «полупустого» ряда.
5. **Соседние блоки на узких ширинах** (после правок иконок не перепроверялись): `.step`
   в 2 колонки на ≤860px с иконкой 55px, `.hero__portrait` 116px на ≤720px, шапка с
   `white-space: nowrap` на ≤480px, поиск в одну колонку на ≤420px, фильтры каталога
   нижним листом на ≤1024px.
6. **Клавиатура и скринридер** на мобильной раскладке обеих страниц: `Tab` до стрелок карусели
   и до «Все новости», `←/→`, `Home/End`, корректное озвучивание `aria-controls` / `aria-live`
   (статус «Пост N из 3») / `aria-pressed`; ссылка «Все новости» должна читаться как переход
   на другую страницу (не как кнопка «показать ещё»). Проверить, что при фокусе на стрелке
   страница не «прыгает» между постами разной высоты.
7. **`@media print` и `prefers-reduced-motion`** для новых блоков: `.tg-feed--grid` не должен
   разваливаться при печати, карусель — разворачиваться в список постов, `.tg-carousel__nav`
   и `.route__arrow` — скрываться (они декоративные); при `prefers-reduced-motion` листание
   без анимации (уже учтено в `smooth()`), проверить на реальной ОС.
8. **Визуальный регресс:** добавить в `_shots/` скриншоты Telegram-блока и «Маршрута сделки»

## 8. Как проверять и публиковать

```powershell
# локальный сервер (или двойной щелчок по start.cmd)
powershell -NoProfile -ExecutionPolicy Bypass -File .\serve.ps1
# → http://127.0.0.1:5173/index.html , /catalog.html , /telegram.html

# статические проверки → отчёт в _check.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\_check.ps1

# лента Telegram-канала → prototype/assets/js/telegram-data.js
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\fetch-telegram.ps1 -Channel '@hazieva_realty'

# публикация из копии репозитория (сообщение с кириллицей — только через файл)
git add -A
$tmp = "$env:TEMP\msg.txt"
[IO.File]::WriteAllText($tmp, 'сообщение коммита', (New-Object Text.UTF8Encoding($false)))
git commit -F $tmp; Remove-Item $tmp -Force
git push origin main
# затем 1–2 мин на GitHub Actions и Ctrl+F5 на сайте
```

## 9. Грабли, на которые уже наступали

1. **Headless Chrome не делает окно уже ~500px** → узкие ширины меряются через `<iframe>`
   нужной ширины (`_shots/frame.html`, `_shots/frame-catalog.html`).
2. **Скриншоты в этой среде падают** (exit 13) — вместо них `--dump-dom` + `getBoundingClientRect`
   / `getComputedStyle` в пробном файле.
3. **Глобальный `:focus-visible` задаёт `border-radius: 4px`** — круглым кнопкам радиус нужно
   возвращать явно (`.route__arrow:focus-visible`).
4. **`justify-content: space-between` в grid** не прижимает элементы к краям сам по себе —
   нужны `justify-self: start/end`.
5. **`hidden` не работает, если класс задаёт `display`** — для `.btn`/`.tag`/`.tg-*` нужны
   явные правила `[data-…][hidden] { display: none !important; }`.
6. **Скрипты `*.ps1` должны быть в UTF-8 с BOM**, иначе Windows PowerShell 5.1 ломает кириллицу.
7. **Git-коммиты с кириллицей** — только через файл UTF-8 без BOM и `git commit -F`
   (так делает `deploy.ps1`).
8. **GitHub Pages кэшируется** — без `Ctrl+F5` видна старая версия `site.css`/`app.js`.
9. **Временные пробники** (`prototype/_probe*`, `_shot*`, `_live_*`, `_dom.html`) нужно удалять
   после проверки, иначе они попадают в публикуемую папку `./prototype`.
10. **Параллельные публикации** Pages иногда падают — в `deploy.yml` добавлена группа
    `concurrency: pages`, после этого деплои стабильны.
11. **Рабочая папка может «откатить» репозиторий** — `deploy.ps1` копирует её поверх
    `my_website`; перед деплоем из неё нужно синхронизировать файлы в обе стороны.
